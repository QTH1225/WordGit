# 发布说明

## 当前版本

WordGit 0.10.5 将侧栏本地操作排列为两列等宽按钮，远程同步单独分组并使用四列等宽按钮，统一按钮高度、文字居中与间距，避免窄窗格中零散换行。功能区的两字、三字标题保持单行，四字标题按两个字一行显示；“导入审阅稿”等较长标题按动作与对象分为两行。使用断行标记固定分组，保留 Word 原生图标和按钮。0.10.2 移除手动存储整理入口，空闲时的自动维护保留，用户无需点击按钮。0.10.1 的功能区调整继续保留：分组名改为“本地提交”，“取回版本”移到“远程协作”之后、“关于与更新”之前。存储整理仍由后台自动维护。0.10.0 增加单稿件 GitHub 仓库关联、克隆、获取、推送和拉取；侧栏显示远程分支与领先、落后数量。分歧通过 Word 原生修订生成双父合并提交，获取前保留已下载远程版本。沿用现有存储格式。临时比较副本先激活窗口再处理修订，避免隐藏文档的 COM 状态异常。0.9.8 的“导入审阅稿为分支”继续保留：按原始字节保存外部返稿，以所选送审版为父提交，并通过 Word 原生修订审阅建立双父合并提交。导入不切换当前分支；批注与修订保留在原始返稿提交中。0.9.7 的版本、作者、链接与更新检查，以及 0.9.6 的流式文件路径和历史存储格式继续保留。新分块历史内容按流处理；分块索引仍占用内存，旧整包与拆包历史使用兼容读取路径。0.9.5 整理了独立安装维护程序、ZIP 发布包和安装文档，保留 0.9.4 的旧拆包历史兼容修复。安装、升级与卸载均保留历史仓库和审阅稿。

项目主页为 https://github.com/QTH1225/WordGit，更新检查查询该仓库的最新正式 Release。本地生成安装包或提交源码不代表已经发布更新；维护者需将安装包与校验文件上传到正式 Release，并采用 v0.10.5 这类数字版本标签。普通标签和预发布不会由“检查更新”作为正式更新提供。

## 生成与发布

1. 在开发机运行 package.ps1 -Test，并执行 build.ps1 -WordTest。
2. 核对 EXE、ZIP 的版本与 SHA256SUMS.txt。
3. 在准备发布的位置上传两个安装文件和校验文件，并附上相同版本标签对应的完整源码；源码包含 src、packaging、tests、docs、根目录构建与安装脚本及 LICENSE。
4. 发布说明写明验证过的 Windows、Word 位数、Git 版本和已知限制。
5. 核对作者 QTH1225、项目链接与 GPL-3.0-only 许可证，正式分发时配置发布者代码签名。

当前安装包未进行代码签名，不能宣称已签名或已通过所有 Windows/Office 版本认证。现有 Word 实机验证以本机 64 位 Word 为准；32 位 Word 的注册路径有测试覆盖，完整功能仍需补充实机验证。

安装文件校验只验证包内数据是否完整。包本身的来源和发布者身份仍应通过可信发布渠道和代码签名确认。

## 远程验证范围

远程回归使用两个隔离客户端和本地裸仓库，覆盖关联、克隆、快进、分歧合并、拒绝非快进推送、并发变化、无共同历史、更换地址、远程历史改写后的保留，以及不覆盖已有文档和仓库。

Word 实机测试使用同样的双客户端场景，核验原生修订、作者和批注、图片、表格、页眉、页边距、合并提交父节点，以及未保存编辑的保护。真实 GitHub HTTPS / SSH 的账号认证和仓库权限，需要用户在目标仓库上完成首次连接验证；没有将测试文档上传到真实 GitHub。

## 升级与数据保护

安装器只操作 app 中已知的插件组件和当前用户注册信息，不删除 repositories、sessions 或源文档，也不运行仓库迁移、清理或重写命令。

发布前应保留跨格式回归测试：整包、旧拆包和新分块版本均能读取，混合历史可继续提交，压缩后旧版仍可取回。旧拆包版本只保证部件一致，不能补回该格式从未记录的原 ZIP 编码与时间戳。

## 本轮发布包范围

发布采用文件清单：插件 DLL、安装维护程序、启动脚本、README、使用与开发说明、发布说明和包内校验清单。用户数据、测试输出及恢复副本不属于发布内容。
