# 使用 WordGit

## 保存版本与查看历史

打开已保存的本地 DOCX，点击 WordGit 选项卡中的“提交版本”，或右侧窗格中的同名按钮。填写提交说明后，Word 先保存当前稿，插件再在后台计算并写入新增数据块。之后继续编辑的内容可另作下一次提交。

右侧窗格上半部分按位置列出批注和修订，显示类型、作者与页码。点击跳转，悬停查看内容；可筛选全部、批注或修订。选中修订后点击“接受”或“拒绝”，使用 Word 原生操作处理并自动定位下一条。到末尾会回到前面尚未处理的修订；全部处理完后显示完成提示。可使用 Word 的 Ctrl+Z 撤销操作。

下半部分显示当前分支、修改状态和提交图。拖动分隔条可以调整上下大小。选择旧提交后可预览或对比；按 Ctrl 选择两个提交可以比较两版。对比结果由 Word 生成。

“对比最新提交”比较当前稿与当前分支的最新提交，包括未保存的编辑。插件使用临时副本的最终内容进行比较，原稿已有的修订与批注保留。

## 本地分支与合并

1. 点击“新建分支”，选择起始版本并输入分支名。
2. 点击“切换分支”，选择目标分支。当前稿有未提交修改时，会询问是否先提交。
3. 点击“合并分支”，选择要合入当前分支的来源分支。插件寻找共同祖先，再由 Word 原生比较和合并生成独立审阅稿。
4. 在审阅稿中逐条接受或拒绝修订。
5. 完成审阅后点击“提交版本”，将确认结果写回原稿并建立两个父提交的合并记录。

审阅未确认前两个分支保持原状；分支或原文件在审阅期间发生变化时，插件会拒绝覆盖。分支删除仅允许删除已经合入当前分支的其他本地分支，当前分支不可删除。

“合并审阅稿”也可用于导师返稿：选一个历史基准与一份外部返稿，或按 Ctrl 选两个历史版本，交给 Word 生成修订稿。审阅稿保存在 sessions 目录，保留其路径可在重启后继续审阅。

## 取回旧版

- “预览”以只读方式打开旧版本。
- “另存旧版”将旧版本导出到新的 DOCX 路径。
- “恢复旧版”先归档当前稿，再替换原文件并建立新提交。

原地恢复、分支切换和确认合并要求原稿位于非同步的本地目录。OneDrive 等同步目录中的文档可以使用预览和另存功能。

当前没有远程推送、拉取或实时多人共编功能。WordGit 管理本地 Git 历史，Word 继续负责排版、比较和修订。跨电脑预览时，字体、Word 版本、字段更新和打印设置仍可能影响分页。

## 空间与历史压缩

新提交复用已经保存的相同数据块，新增变化的数据和版本清单；并非每次在硬盘多复制一整份 DOCX。图片被替换或 Word 重写压缩数据时，新增量仍可能较大。

每累计约 10 次新提交，插件在键鼠空闲约 20 秒时，以低优先级、单线程在后台整理 Git 存储。也可点击“压缩历史”立即处理。提交号与版本内容保留，三种历史格式都支持继续读取。

历史不会全部常驻内存。0.9.6 起提交、还原、预览、导出和合并均为流式读写，按数据块分段处理，内存峰值与文档大小基本无关；提交期间若检测到文档被其他程序改写会中止并提示重新提交，不会产生错误版本。手动压缩当前也未设置与自动压缩相同的资源限制。备份、导出的恢复文档和 sessions 文件不在“压缩历史”的处理范围内。

## 历史格式兼容

整包与新分块历史按原文件字节取回。旧拆包历史会逐一验证所有 DOCX 部件的长度、SHA-256 和整体指纹后重建文件；文档部件保持一致，但原 ZIP 容器编码和时间戳未保存，不能承诺整个 ZIP 文件逐字节一致。安装和升级不改写这些旧提交。
