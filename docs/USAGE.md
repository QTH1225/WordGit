# 使用 WordGit

## 保存版本与查看历史

打开已保存的本地 DOCX，点击 WordGit 选项卡中的“提交版本”，或右侧窗格中的同名按钮。填写“提交标题”，按需在“详细内容”中记录修改说明，点击“提交”或按 Ctrl + Enter。Word 先保存当前稿，插件再在后台计算并写入新增数据块。之后继续编辑的内容可另作下一次提交。

右侧窗格上半部分按位置列出批注和修订，显示类型、作者与页码。点击跳转，悬停查看内容；可筛选全部、批注或修订。选中修订后点击“接受”或“拒绝”，使用 Word 原生操作处理并自动定位下一条。到末尾会回到前面尚未处理的修订；全部处理完后显示完成提示。可使用 Word 的 Ctrl+Z 撤销操作。

打开提交图后，右侧先显示固定的批注、修订与提交框架，并提示“正在加载”。记录和分支读取完成后统一显示内容，修改状态在后台检查；加载期间可继续编辑正文。同一稿件再次点击“提交图”或关闭后重新打开，会直接复用已有内容，保留分支筛选和选中版本。需要重读仓库时点击“刷新”；提交、切换分支和远程操作后会自动更新。批注与修订列表约每 5 秒检查一次是否有增删，有变化时才重新读取页码等信息，长文档编辑时不会周期性卡顿；最晚约 30 秒也会完整刷新一次，也可随时点击“刷新”。下半部分显示当前分支、修改状态和提交图。拖动分隔条可以调整上下大小。选择旧提交后可预览或对比；按 Ctrl 选择两个提交可以比较两版。对比结果由 Word 生成。

“对比最新提交”比较当前稿与当前分支的最新提交，包括未保存的编辑。当前稿已保存时直接使用磁盘上的文件；有未保存编辑时，插件使用临时副本的最终内容进行比较，原稿已有的修订与批注保留。

提交、导入、推送等后台操作按稿件分别进行：一份稿件正在提交时，其他稿件不受影响。后台操作未完成时关闭 Word，会出现等待提示，操作完成后 Word 继续退出。

## 本地分支与合并

1. 点击“新建分支”，选择起始版本并输入分支名。分支名不能包含空格和 `~ ^ : ? * [ \ " < > |`，也不能使用 CON、NUL、COM1 等 Windows 保留名称或以句点结尾。
2. 点击“切换分支”，选择目标分支。当前稿有未提交修改时，会询问是否先提交。
3. 点击“合并分支”，选择要合入当前分支的来源分支。插件寻找共同祖先，再由 Word 原生比较和合并生成独立审阅稿。两个分支曾经互相合并、存在多个共同祖先时，使用 Git 选出的其中一个作为基准，审阅稿中可能多出一些已经处理过的修订，逐条确认即可。
4. 在审阅稿中逐条接受或拒绝修订。
5. 完成审阅后点击“完成合并”，将确认结果写回原稿并建立两个父提交的合并记录。

审阅未确认前两个分支保持原状；分支或原文件在审阅期间发生变化时，插件会拒绝覆盖。分支删除仅允许删除已经合入当前分支的其他本地分支，当前分支不可删除。

## 返稿合并

1. 在原稿中提交送审后做的修改。点击功能区或右侧窗格的 **返稿合并**。
2. 在窗口中选择对方返回的 DOCX，从「送审版本」选中实际发出的版本，并核对「合入分支」。
3. 勾选 **将原始返稿保存为独立分支** 时，填写分支名（如 `review-老师一审`）和来源。可以点击 **仅保存为分支**，之后再通过 **合并分支** 处理。
4. 点击 **生成合并稿**。右侧窗格显示剩余修订数，全部处理后点击 **完成合并**，更新当前稿。批注可以保留。

勾选保存分支时，原始返稿按原始字节存入历史，批注和修订可以随时预览。最终合并提交会关联当前稿和返稿分支。取消勾选时，最终结果记录为当前分支的一次提交。两种方式都会纳入当前分支在送审后已经提交的修改。

原地合并要求原稿位于非同步的本地目录。合并稿保存在 sessions 目录，可在重启后通过该文件继续审阅。只想合并历史中的两版时，点返稿窗口中的 **合并两个历史版本**，再按 Ctrl 选两版。

```text
送审 A ── 你继续修改 B ── 合并确认 M
    └──── 老师原始返稿 T ──────┘
```

## 取回旧版

- “预览”以只读方式打开旧版本。
- “另存旧版”将旧版本导出到新的 DOCX 路径。
- “恢复旧版”先归档当前稿，再替换原文件并建立新提交。

切换分支和恢复旧版在后台进度窗口中执行，期间请不要编辑当前稿；完成后文档会自动重新打开。替换原文件前插件会记录操作意图：如果 Word 在替换途中退出，下次启动时会自动还原到操作前的内容（分支尚未切换时）或保留新内容（分支已经切换时），并弹出说明。

原地恢复、分支切换和确认合并要求原稿位于非同步的本地目录。OneDrive 等同步目录中的文档可以使用预览和另存功能。WordGit 生成的预览、对比稿位于 sessions 目录，没有自己的版本历史，不能直接提交；需要保留时请先另存到其他位置。

WordGit 支持通过 GitHub 进行按版本协作，Word 负责排版、比较和修订。跨电脑预览时，字体、Word 版本、字段更新和打印设置仍可能影响分页。实时同屏共编不在本版范围内。

## 一份稿件关联一个 GitHub 仓库

### 第一位作者：关联已有历史

1. 打开原稿，先提交当前修改。
2. 在 GitHub 创建空仓库，保留分支初始化给 WordGit；给协作者授予相应访问权限。
3. 点击 **关联仓库**，填写 HTTPS 地址（如 `https://github.com/owner/paper.git`）或 SSH 地址，以及远程分支名。
4. 点击 **关联并获取**。此操作不会上传或覆盖正文。
5. 点击 **推送**，上传当前分支的已提交历史。

每份文档的远程关联保存在其本地历史仓库中。它沿用原来的提交号、父子关系、分支和存储格式；不重新初始化已有历史。更换仓库地址会先归档旧的远程跟踪版本，再切换地址；旧提交仍可在全部历史中查找。

### 其他作者：克隆为新的本地稿件

点击 **克隆稿件**，填写仓库地址、远程分支和新的本地 DOCX 文件名。插件下载分支和对象，校验并还原文档，将本地分支关联到所选远程分支。新电脑上的文件名和路径可以不同。

克隆不会覆盖现有文件或该路径已经保留的历史仓库。原地拉取与合并继续要求文档位于非同步的本地目录。源仓库必须包含 WordGit 历史；网页直接上传的普通 DOCX、普通代码仓库和空分支不能直接作为 WordGit 稿件克隆。

### 日常协作与分歧合并

1. 各自修改并 **提交版本**。
2. 点击 **获取**，查看远程分支及领先、落后数量。获取只下载历史。
3. 点击 **拉取**。只有对方新增提交时，插件校验工作文件后快进到远程版本；已有提交号不变。
4. 双方均有独立提交时，插件使用共同祖先和双方文档生成 Word 原生修订稿。正文原稿和双方提交在审阅期间保持原状。
5. 逐条阅读批注、接受或拒绝修订，完成后点击 **完成合并**，将确认稿写回原稿并建立两个父提交的合并记录。
6. 回到原稿点击 **推送**，再由其他作者获取、拉取该合并版本。

拉取不会覆盖未保存或未提交的本地修改。审阅期间本地分支、已获取的远程分支或原文件发生变化时，插件要求重新操作。推送使用普通 Git 非强制更新；对方先推送了新版本时，当前推送会被拒绝，需要先获取、合并。

提交图中的 `origin/分支名` 为已经获取的远程跟踪分支。可在分支筛选中查看其历史，也可预览和对比对应版本。同步数量以最近获取或推送为准，插件不自动轮询网络。

获取后，如果服务器上的某个分支被强制改写（新版本不再包含之前下载的版本），插件会把改写前的版本归档到本机；被服务器删除的分支也不会自动清理。远端重写历史后，本机已经下载的旧版本仍可取回。普通的快进更新不产生归档。推送只处理当前本地分支；未推送分支和仅在本机的归档继续保存在本机。本版未提供远程标签同步、远程分支删除或强制推送入口。

### 登录与连接

HTTPS 使用 Git for Windows 配置的凭据管理器，插件不保存口令或令牌。首次连接可能打开浏览器登录；也可先按 [GitHub 官方说明](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git) 配置 Git Credential Manager 或 GitHub CLI。SSH 使用预先配置的密钥，插件不会通过终端索要口令；在 Git 中设置过 `core.sshCommand`（例如使用 PuTTY 的 plink 或指定密钥）时沿用该设置，否则首次连接会自动记录 GitHub 的主机密钥。

网络操作没有总时长限制，大仓库首次克隆在慢速网络下也能完成；连续约 3 分钟没有任何传输进展时自动停止。点击“取消”会同时结束 Git 启动的所有辅助进程。获取时会校验下载对象的结构，格式异常的对象会被拒绝。

克隆得到的稿件带有 Windows 的“来自网络”标记，之后在资源管理器中直接打开时，Word 可能先以受保护视图显示，确认来源后点击“启用编辑”即可。

GitHub 拒绝访问、网络超时或权限不足时，操作窗口会显示 Git 的错误。关联配置可保留供重试，已有本地历史和文档不删除。本版仅接受 GitHub HTTPS / SSH 地址；测试使用隔离的本地 Git 远程。GitHub 对旧整包大文件的限制仍适用，失败时不会通过改写历史自动绕过限制。

## 空间与历史压缩

新提交复用已经保存的相同数据块，新增变化的数据和版本清单；并非每次在硬盘多复制一整份 DOCX。图片被替换或 Word 重写压缩数据时，新增量仍可能较大。

每累计约 10 次新提交，插件在键鼠空闲约 20 秒时，以低优先级、单线程在后台整理 Git 存储。日常整理只合并较小的数据包，开销与历史总大小无关；约每 30 天做一次完整整理，并清除两周前就已不被任何版本引用的数据（例如中途失败的提交留下的数据块）。维护由插件自动执行，界面不提供手动按钮。提交号与版本内容保留，三种历史格式都支持继续读取。每次提交在报告成功前都会把数据写入磁盘，突然断电不会让已提交的版本损坏。

历史不会全部常驻内存。提交、还原、预览、导出、对比、合并和新建分支都通过文件流和分块缓冲处理内容，三种历史格式都是如此；分块清单与索引仍随块数增长。Word 本身的加载、排版与比较也会占用内存。提交期间若检测到文档被其他程序改写会中止并提示重新提交。已加密或设置了打开密码的文档无法提交，请先在 Word 中取消密码保护。

另存旧版时，文件在完整校验后才会出现在所选位置；取回失败不会留下损坏的文档。

## 版本信息与更新

WordGit 功能区的“关于与更新”组、右侧窗格底部均可查看当前版本。点击版本信息，查看作者、许可证，以及 GitHub 仓库、发布页和反馈问题入口。

点击“检查更新”后会在独立窗口中异步查询 GitHub 正式 Release，编辑区可以继续操作。关闭窗口会取消查询。没有可用正式版本、请求超时、网络失败或 GitHub 限流时会分别提示；查询本身不读取文档或历史仓库。发现新版本后点击“发布页”下载安装包，再保存并关闭 Word 进行安装。

## 历史格式兼容

整包与新分块历史按原文件字节取回。旧拆包历史会逐一验证所有 DOCX 部件的长度、SHA-256 和整体指纹后重建文件；文档部件保持一致，但原 ZIP 容器编码和时间戳未保存，不能承诺整个 ZIP 文件逐字节一致。安装和升级不改写这些旧提交。
