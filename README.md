# WordGit 0.9.5

在 Windows 桌面版 Microsoft Word 中管理本地 Git 历史。直接提交当前稿、查看分支与提交图、预览和对比旧版本，并使用 Word 原生修订进行合并审阅。

## 普通用户安装

### 1. 准备运行环境

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11，x86 或 x64 |
| 编辑器 | 已安装 Windows 桌面版 Microsoft Word |
| Git | [Git for Windows 2.51 或更新版本](https://git-scm.com/install/windows) |
| 运行时 | [.NET Framework 4.8 或更新版本](https://dotnet.microsoft.com/download/dotnet-framework/net48) |

安装程序会检查这些条件。Git 和 .NET 需单独安装，发布包不包含它们。普通用户不需要 Visual Studio、PowerShell 7、VSTO 工具包或编译源码。

安装脚本会识别 Word 的位数并选择对应注册表视图。目前已在 64 位 Word 实机验证；32 位 Word 的完整功能仍需更多实机验证。WPS、网页版 Word、Mac 版 Word 和 ARM 原生 Word 不在当前支持范围内。

### 2. 安装 WordGit

1. 获取发布者提供的 **WordGit-0.9.5-Setup.exe**。
2. 保存文档，并关闭所有 Word 窗口。
3. 双击安装程序，点击 **安装 / 更新**。安装仅作用于当前 Windows 用户，通常无需管理员权限。
4. 安装成功后重新打开 Word，顶部应出现 **WordGit** 选项卡。

也可以使用 ZIP 包：完整解压 `WordGit-0.9.5-windows.zip`，进入解压后的文件夹，双击 `WordGit.Setup.exe`。需要在控制台查看完整输出时，可双击 `Install.cmd`；`Check.cmd` 只检查环境和文件，不执行安装。

安装结束后可以删除下载的 EXE 或解压文件夹。插件和维护程序已复制到 `%LOCALAPPDATA%\WordGit\app`。

## 升级：保留现有历史

保存并关闭 Word，运行新版安装程序，再点击 **安装 / 更新**，不需要先卸载旧版。

- 更新程序只替换插件组件和当前用户的加载注册信息。
- 不删除、重新初始化、迁移或改写 `repositories` 中的 Git 仓库。
- 不改动用户文档或 `sessions` 中的审阅稿。
- 原提交号、父子关系、分支和标签继续保留。

当前读取器兼容三种存储格式：

| 历史格式 | 取回方式 |
| --- | --- |
| 整包 `document.docx` | 按原始文件字节取回 |
| 旧拆包：`wordgit.meta` 与 DOCX 部件 | 校验每个部件长度、SHA-256 和整体部件指纹，再重建 DOCX |
| 新分块：`wordgit.snapshot` 与共享数据块 | 按清单重建并校验原始文件 SHA-256 |

旧拆包格式没有保存原 ZIP 容器的压缩编码和时间戳，因此保证文档部件一致，不能保证重新封装后的 DOCX 与当时原文件逐字节相同。整包与新分块格式支持逐字节恢复。0.9.4 已修复旧拆包历史读取失败的问题，0.9.5 包含该修复；不要降级到不支持对应格式的旧插件。

## 第一次使用

1. 打开一份已保存的本地 `.docx`。新文档建议保存在非同步的本地文件夹中。
2. 点击 **WordGit → 提交版本**，填写说明，建立第一条历史。
3. 点击 **提交图**，在右侧查看历史。侧栏下方也有 **提交版本** 按钮。
4. 选中旧提交，点击 **预览** 或 **对比当前稿**；也可以 **另存旧版**，将它取回为一个新的 DOCX。
5. 合并审阅时，在上方列表选中修订，直接点击 **接受** 或 **拒绝**，处理后自动定位下一条。审阅完成后再提交版本。

更多操作见 [使用说明](docs/USAGE.md)。

## 卸载与重新安装

保存并关闭 Word，然后任选一种方式：

- Windows **设置 → 应用 → 已安装的应用** 中找到 **WordGit**，选择卸载，并在维护窗口中点击 **卸载**。
- 重新运行安装程序，点击 **卸载**。
- 在 ZIP 解压目录中双击 `Uninstall.cmd`。

卸载会移除插件组件和加载注册信息，**保留文档、历史仓库和审阅稿**。同一 Windows 用户重新安装后，在原路径打开文档即可继续访问原来的历史。

## 数据位置与备份

| 目录 | 内容 |
| --- | --- |
| `%LOCALAPPDATA%\WordGit\app` | 插件与安装维护程序 |
| `%LOCALAPPDATA%\WordGit\repositories` | Git 历史仓库 |
| `%LOCALAPPDATA%\WordGit\sessions` | 预览、比较和合并审阅文件 |

备份历史时，关闭 Word 后复制整个 `repositories` 文件夹；需要保留未完成的合并审阅时也复制 `sessions`，并单独备份原文档。安装、升级和卸载均不会自动删除这些数据目录。

历史通过文档的完整路径定位。移动或重命名文档后会使用新的历史位置，原仓库仍保留。同步目录中的文档可以预览或另存旧版；原地切换、恢复和合并等覆盖操作受限。

## 常见问题

**Word 中没有 WordGit 选项卡**

先关闭所有 Word 窗口后重新打开；然后检查 **文件 → 选项 → 加载项 → 管理 COM 加载项 → 转到** 中是否启用 WordGit。可以重新运行安装程序进行检查和安装。受单位策略管理的 Office 可能需要管理员协助允许加载插件。

**提示找不到 Git**

先安装 Git for Windows。插件会搜索 PATH 和常用安装目录。自定义安装路径可在 PowerShell 中设置后重新打开 Word：

```powershell
[Environment]::SetEnvironmentVariable('WORDGIT_GIT', 'D:\Tools\Git\cmd\git.exe', 'User')
```

将路径替换为实际的 `git.exe`。设置错误时应更正该变量。

**压缩历史后还能预览和恢复吗？**

可以。压缩历史使用 Git 对象打包与差分压缩，保留提交和分支关系。它不会将多个提交合并成一版，也不会迁移旧版存储格式。新提交已共享相同数据块；压缩后的进一步收益取决于数据。

**当前包是否已经签名？**

当前为未签名的预览发布包。维护者提供 SHA-256 校验值，正式公开分发前还应完成发布者身份与代码签名配置。签名和额外电脑兼容性测试的状态见 [发布说明](docs/RELEASING.md)。
